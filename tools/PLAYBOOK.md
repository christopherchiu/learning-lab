# Learning Lab playbook

The Learning Coach agent follows this for every lesson, progress update and discovery run.


Everything lives in the public repo **christopherchiu/learning-lab** (branch `main`, served by GitHub Pages).

- Reading site: https://christopherchiu.github.io/learning-lab/
- Podcast feed (Chris follows it in Apple Podcasts; syncs to his Apple Watch): https://christopherchiu.github.io/learning-lab/feed.xml
- `library/` is the source of truth. Root files (index.html, lessons.json, feed.xml, lessons/*/lesson.html) are generated by `scripts/build_app.py`. Never hand-edit generated files.

Scripts live in this repo under `tools/`. Always run them with the literal absolute path, e.g. `python3 /home/user/learning-lab/tools/scripts/narrate.py` (a shell variable in the path gets the script rejected with tool_not_allowed).

## 1. Load state (every run)

```bash
cd /home/user && rm -rf learning-lab && git clone -q https://github.com/christopherchiu/learning-lab
cat learning-lab/library/progress.json
ls learning-lab/library/lessons
```
Read `progress.json` before writing anything: it says what Chris already knows, how deep, what he found too easy/hard, and what's queued. Don't re-teach covered ground; build on it and reference earlier lessons by title.

## 2. Research

Goal: understand the source better than the source explains itself.
- Read the link itself (firecrawl / web fetch). For X/Twitter links, fetch the tweet and thread via an Apify tweet scraper or exa `category: "tweet"`; nitter-style mirrors are unreliable.
- Find what's behind it: the paper, repo, benchmark, blog post or announcement it references. Read the primary source, not summaries.
- Map the conversation: related posts gaining traction, notable quote-tweets and replies, credible pushback, prior work it builds on. Use exa (tweet, research paper, news categories) and parallel/web search. Prefer recent, high-signal voices (researchers, practitioners, the authors).
- Keep a list of every source URL you actually used. Never invent quotes, numbers, benchmark results or attributions. If something is unverified, say so in the lesson.

## 3. Write the lesson (`library/lessons/<slug>/lesson.md`)

Slug: `YYYY-MM-DD-short-kebab-title` (Pacific date).

Bar: reads like an Anthropic or OpenAI engineering/research blog post. Concretely:
- A title that states the idea, not a clickbait question. One-paragraph lede saying what this is and why it matters now.
- Build intuition first (a concrete example, analogy or toy problem), then the mechanism, then the nuance. Explain *why* it works and where it breaks.
- Precise, plain language. Define terms on first use. Short paragraphs. Headers (`##`) for sections. Code blocks, tables or small worked examples where they genuinely help.
- A "The conversation" section: who's saying what, where they disagree, what's unsettled. Link sources inline.
- A "Why it matters for you" angle when relevant (Chris is an engineering leader: systems, teams, product, strategy).
- End with "Key takeaways" (3-5 bullets) and "Sources".
- Default length 1,400-2,000 words (≈10-13 min audio). Shorter for a single narrow tweet; Chris can ask for longer.

## 4. Write the narration (`library/lessons/<slug>/narration.txt`)

A script for the ear, adapted from the lesson (not a read-aloud of markdown):
- No markdown, URLs, code or tables. Describe code and tables in words ("the function takes a list of tokens and returns...").
- Open with a one-line hook and what the listener will understand by the end. Signpost sections ("Okay, so how does it actually work?").
- Spell out symbols and abbreviations the first time (say "K V cache", "two times faster"). Numbers as spoken.
- Close with a 3-question recap quiz: ask each question, pause line ("Take a second."), then give the answer.
- Paragraphs separated by blank lines (the narrator chunks on them).

## 5. Narrate

```bash
python3 /home/user/learning-lab/tools/scripts/narrate.py learning-lab/library/lessons/<slug>/narration.txt learning-lab/audio/<slug>.mp3
```
Prints `{"duration_secs", "cost_usd", ...}`. Default voice Brian (`nPczCjzI2devNBz1zQrb`), model `eleven_multilingual_v2`; `--voice` to change if Chris asks. Roughly $0.17 per minute of audio. Run `--estimate` first if a script exceeds ~20k characters and tell Chris the cost before narrating.

## 6. Metadata + progress

`library/lessons/<slug>/meta.json`:
```json
{
  "title": "...", "summary": "1-2 sentences, shown in Podcasts show notes",
  "source_type": "tweet|blog|paper|thread|video|topic", "source_url": "https://...",
  "topics": ["Inference", "LLMs"], "created_at": "<UTC ISO8601>", "duration_secs": 612.4,
  "quiz": [{"q": "...", "a": "..."}],
  "related": [{"title": "...", "url": "https://...", "why": "one line"}]
}
```

Update `library/progress.json`:
- `concepts`: add/upgrade entries `{"name", "level": "intro|working|deep", "lessons": [slugs], "last_seen": date}`.
- `suggested_next`: keep 3-6 items `{"topic", "why", "source_url"}`, ranked; drop ones now covered.
- `feedback_log`: append any feedback Chris gave this run `{"date", "lesson", "note"}`.
- `listened`: when Chris says he listened/skipped, record `{"slug", "status": "listened|skipped|partial", "date"}`.
- `learner`: refine stated preferences only when Chris states them.

## 7. Build and publish (one commit)

```bash
cd /home/user/learning-lab && python3 /home/user/learning-lab/tools/scripts/build_app.py .
```
Then save the MP3 so the GitHub connector can read it (git push is not available):
`manage_artifact save {file: {path: "/home/user/learning-lab/audio/<slug>.mp3"}, name: "<slug>.mp3"}` and take `files[0].filename` (the Storage Path).

```bash
python3 /home/user/learning-lab/tools/scripts/publish.py . "Lesson: <title>" \
  --text index.html app.js styles.css theme.css manifest.webmanifest .nojekyll lessons.json feed.xml \
         lessons/<slug>/lesson.html library/progress.json \
         library/lessons/<slug>/lesson.md library/lessons/<slug>/narration.txt library/lessons/<slug>/meta.json \
  --binary "audio/<slug>.mp3=<storage path>"
```
For progress-only changes, commit just `library/progress.json` and `lessons.json` (after rebuilding).

## 8. Verify and report

Wait ~60s for Pages, then check `curl -sI https://christopherchiu.github.io/learning-lab/audio/<slug>.mp3` returns 200 and feed.xml contains the slug. Report to Chris: title, 2-sentence gist, length, link `https://christopherchiu.github.io/learning-lab/#/<slug>`, and that it'll appear in Podcasts on next refresh. Send the MP3 artifact too so he can listen right away.
